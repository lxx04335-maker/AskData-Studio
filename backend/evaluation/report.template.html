这次真正发现的问题：同名 CTE 绕过表级权限检查

在受限测试身份下，CTE 的名称和无权访问的物理表相同。原逻辑按全局名称过滤表引用，误把内部真实表排除，返回了 480 条历史订单的计数。修复改为按 SQL 作用域解析物理来源表。

只改执行器的表引用识别；模型、提示词、检索参数、数据和原始 28 条任务不变。两条扩展边界题由阅读源码后设计，不作为盲测样本。

查看复现 SQL 与修复方法
WITH orders_history AS (
  SELECT order_id FROM orders_history
)
SELECT COUNT(order_id) AS n FROM orders_history;

内层来源应解析为物理 Table 并检查权限；外层来源为派生 Scope。不能把所有同名引用都排除，也不能简单禁止全部 CTE。

负例必须拒绝

无权历史表的同名 CTE；允许库但没有任何表权限的同名 CTE。

正例必须保留

有权表与 CTE 同名；CTE 起名像无权表，但内部只读取有权表。

怎样理解这些数字

  • 19 条数值查询、6 条行为检查、5 条安全边界分别看；混合通过率不能叫模型问数准确率。

  • 代码与数据快照、配置和哈希均保留。测试并发且轮次曾短暂重叠，耗时用于诊断，不宣称性能提升。
